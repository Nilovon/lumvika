title: "Review"
description: "Approve the work your coworkers hand back, send it back with a comment, unblock what is stuck."
---

**Review** is the queue of what waits on a person, in three tabs. It reads every project you can open, so a teammate's issue shows up too.

## To review

The issues in **In review**. Each card says who moved it there (**Finished by Scout**), when, and the last comment, which is usually the coworker's summary of what it did and where to find it.

The ones marked **Yours**, the issues you created or whose project you lead, come first. Then the one waiting the longest.

| Button | What it does |
| --- | --- |
| **Approve** | Moves the issue to **Done** |
| **Request changes** | Asks **What should change**, posts your answer as a comment, and moves the issue back to **In progress**. The coworker is woken and reads your comment first |
| **Open** | Opens the issue, to read the whole thread before deciding |

## Blocked

The issues in **Blocked**, with **Why it is blocked**: the reason the coworker or the person gave, which says who must do what.

**Unblock** puts the issue back in **Todo**, with a comment if you add one. Use it to say what changed: "The export of the old CMS is in the shared folder." A coworker assigned to it is woken.

## Waiting in conversations

The conversations in which a coworker stopped to ask you something: an **Approval**, a **Question**, a **Connection** to an app. **Open conversation** takes you to the card to answer. See [Human in the loop](/agents/human-in-the-loop).

These are not tied to issues: a chat, a scheduled task or an issue run can each end up here.

## Who can decide

Anyone who can open the project approves, requests changes or unblocks. If someone else got there first, the app tells you the issue is no longer waiting for review, or no longer blocked.

A coworker can never approve its own work on an issue a person asked for: that is what this queue is for. See [The rules a coworker follows](/work/coworkers-on-issues#the-rules-a-coworker-follows).

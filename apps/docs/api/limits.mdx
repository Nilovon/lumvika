## Numbers

| Limit | Value |
| --- | --- |
| Active API keys per workspace | 20 |
| API key name | 60 characters |
| API key expiry | None. Revocation only |
| Share link expiry | None. Revocation only |
| Rate limit on the MCP endpoint | None |
| `send_message` wait | 120 seconds by default, 600 maximum |
| `list_runs` | 20 runs by default, 200 maximum |
| `db_query` and `space_db_query` | 100 rows by default, 1000 maximum |
| `list_connectors` | 60 per page by default, 200 maximum |
| Reference files per skill | 200, 10 MB each, 50 MB per skill including `SKILL.md` |
| `read_skill_file` | 100 000 characters per page |
| `get_run` tool call `input` and `result` | 2,000 characters each, the rest replaced by a truncation marker |
| One tool result | 200,000 characters. A larger one is refused with an error asking for a narrower request |
| Webhook request body | 1 MB |
| Payload handed to a coworker by a webhook | 64 KB |
| Paid template price | \$5 minimum, \$2,000 maximum |

Plan quotas still apply. `create_agent` succeeds when the workspace has no free coworker slot, but the coworker comes back with `active: false` and does not run until a slot frees up. See [Plans and billing](/billing).

## Scope

A key reaches one workspace, entirely. Every tool resolves its target through the same ownership check the app uses, so an `agentId` or a `spaceId` from another workspace comes back as `Agent not found` or `Box not found`, never as a partial answer.

There is no read-only key, no per-coworker key and no per-tool permission. If you need a narrower blast radius, use a separate workspace.

## What the API refuses to do

<AccordionGroup>
  <Accordion title="Accept a secret">
    `attach_connector` declares a connector and stops there. API keys, OAuth sign-ins and passwords are entered by the account owner in the app, and they are stored on your machine, never in the Lumvika database. `plan_template_capture` returns credential variable **names** only, never values.
  </Accordion>
  <Accordion title="Publish a template">
    `submit_template` moves a draft to review. Publishing is the Lumvika team's decision. Payout onboarding needs a browser.
  </Accordion>
  <Accordion title="Manage the account">
    No billing, no plan change, no subscription, no member or invitation management, no workspace creation, no Box creation. Create a Box in the app first.
  </Accordion>
  <Accordion title="Manage API keys">
    You cannot mint or revoke a key over MCP. That would let a leaked key extend itself.
  </Accordion>
  <Accordion title="Read coworker memory or files">
    The API covers prompts, skills, schedules, triggers, apps, databases and runs. Memory entries and workspace files are read by the coworker itself, or by you in the app.

    `create_agent_share` is the one place they move at all, and it still never opens them: it can seal them into an archive behind a link, on an explicit `confirm: true`, and hands nothing back to the caller. See [Share link tools](/api/tools/sharing).
  </Accordion>
  <Accordion title="Install a shared coworker">
    The API issues share links, it does not consume them. Opening a link, reading the card and placing the copy on a board is a browser flow, and it needs an active plan on the receiving workspace.
  </Accordion>
  <Accordion title="Upload a file or generate an image">
    `add_template_image` takes a public https URL and re-hosts the bytes. Produce the image elsewhere.
  </Accordion>
</AccordionGroup>

## Guarantees

- **Destructive tools ask twice.** Eight tools refuse to run without `confirm: true`, and `create_agent_share` asks the same way before data leaves the workspace. See [Destructive tools](/api/protocol#destructive-tools).
- **Skills are written atomically.** `upsert_skill` stages the whole folder and swaps it in, so a failed call never leaves a half-written skill.
- **Multi-statement SQL is transactional.** `db_execute` and `space_db_execute` with `statements` apply all of them or none.
- **A tool error is readable.** Failures come back as `isError` results with a message written to be acted on, not as an opaque protocol error. See [Errors](/api/protocol#errors).
- **Renaming is safe.** Changing a coworker `name` re-derives its `handle` and rewrites every `@handle` reference in the other coworkers, so their calls keep resolving.

## Availability

The MCP endpoint and the webhook front door run on the Lumvika app. The coworkers themselves run on your workspace machine. A machine that is shut down or restarting makes coworker-facing tools fail with a reachability error, while catalog tools like `list_connectors` keep working.

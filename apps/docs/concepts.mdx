## Workspace

Your account. It holds your plan, your members, your Boxes and your coworkers, and it runs on one machine: a private computer in the cloud, isolated from every other account, that hosts every coworker of the workspace and holds the files, the databases and the credentials they share. You can belong to several workspaces and switch between them from the pill in the top left corner of the app.

An [API key](/api/authentication) is scoped to exactly one workspace.

## Box

A room of your workspace: on the board it is the rectangle your coworkers sit on. It groups them by team, by client or by project.

A Box is instant and free, and you make as many as the work needs. It arranges coworkers, it does not separate them: every coworker of the workspace runs on the same machine, and the **shared folder** and the **shared database** are common to all of them, whichever Box they sit in.

Because a Box holds nothing of its own, moving a coworker from one to another costs nothing: right-click it on the board and pick **Move to Box**, or ask the Rerun coworker to do it. It keeps its files, its handle, its skills and its whole history.

<Note>
  The Rerun API calls a Box a `space`, in tool names like `list_spaces` and `space_db_query`. Same thing.
</Note>

## Coworker

<Note>
  The Rerun API calls a coworker an `agent`, in tool names like `create_agent` and `list_agents`, and in the `/agents` paths of these docs. Same thing.
</Note>

An AI worker inside a Box. It has:

| | |
| --- | --- |
| **A name** | Free text, what you see. Rename it whenever you want |
| **A handle** | The `@mention` key other coworkers call it by. Renaming the coworker re-derives it and rewrites every `@oldhandle` |
| **A soul** | Its system prompt: who it is, what it owns, how it works |
| **A model** | The provider and model it thinks with, changeable per conversation |
| **Capabilities** | Which families of tools it may use, from files to shell to browser |
| **Memory, skills, files, a database** | All private to it |

## Soul

The coworker system prompt, written in markdown. It is the single most important thing about a coworker. Edit it in the coworker **Settings** tab, or let the coworker rewrite it as it learns.

## Skill

A written procedure the coworker loads on demand, when the task matches its description. It is a folder: a markdown body plus optional reference files.

Skills keep a coworker sharp without bloating its prompt: only a one-line index of every skill is always in context, and the full text loads when it is needed. See [Skills](/agents/skills).

## Memory

Durable facts the coworker writes down and recalls later. Memories fade if nothing uses them, and each recall extends their life, so what matters stays and what does not quietly retires.

Correct a coworker once and it remembers the correction.

## App

A ready-made integration with an external service: Stripe, Gmail, Notion, Slack and hundreds more. Installing one on a coworker gives it that service tools plus a skill explaining how to use them.

An app is installed per coworker, not per Box. See [Apps](/agents/apps).

## MCP server

The open standard Rerun apps are built on. When the library does not have what you need, you can register any MCP server on a coworker yourself, with its own URL, headers or command.

## Run

One execution of a coworker. It starts when you send a message, when a scheduled task fires, when a webhook is called, or when another coworker calls it. It ends when the coworker is done, when it fails, when you cancel it, or when it pauses to ask you something.

Every run records its steps, its tool calls, its tokens and its cost. Read them in the **Monitoring** and **Logs** tabs, or with [`get_run`](/api/tools/runs#get-run).

## Session

A conversation thread with a coworker. A run belongs to a session. Scheduled tasks and webhooks each open their own session, so an automated run never pollutes your chat.

## Scheduled task

A recurring instruction, on a cron and in a timezone, or a one-off at a given date. When it fires, the coworker runs with no user message and follows the instruction. See [Automations](/agents/automations).

## Trigger

A public webhook URL that starts a run when it is called. The caller payload is handed to the coworker alongside your instruction. The URL is the credential. See [Webhook triggers](/api/webhooks).

## Template

A packaged coworker setup, published in the marketplace, that anyone can install into their own workspace in one click. It carries prompts, skills, scheduled tasks, app declarations and files, but never memories or credentials.

Templates can be free or paid. See [Templates](/templates/install).

## Board

The isometric view that is the app itself. Boxes are drawn as rectangles, coworkers sit on them, and clicking a coworker opens its panel.

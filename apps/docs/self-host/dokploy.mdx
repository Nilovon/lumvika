[Dokploy](https://dokploy.com) runs the same `docker-compose.yml` as a manual install, from the published images, then adds the domains and the certificates. Nothing is built on the server.

## Before you start

- A server attached to Dokploy, with at least 4 GB of memory.
- A way to send email, set up as in [Install](/self-host/install#3-set-up-email).
- Three domains pointing at the server, for the app, the engine and the file store: `lumvika.example.com`, `engine.example.com` and `files.example.com`.

## 1. Create the service

1. In a Dokploy project, add a **Compose** service, type **Docker Compose**.
2. Point it at `https://github.com/nilovon/lumvika.git`, branch `main`, compose path `./docker-compose.yml`. Or choose **Raw** and paste the content of [`docker-compose.yml`](https://github.com/nilovon/lumvika/blob/main/docker-compose.yml).

## 2. Set the environment

In the **Environment** tab, set your domains and your mailer. The secrets are generated on the first start, into the `secrets` volume:

```bash .env
NEXT_PUBLIC_APP_URL=https://lumvika.example.com
LUMVIKA_ENGINE_BROWSER_URL=https://engine.example.com
NEXT_PUBLIC_STORAGE_URL=https://files.example.com
RESEND_API_KEY=re_...
RESEND_FROM=Lumvika <lumvika@example.com>
OPENROUTER_API_KEY=sk-or-...
ADMIN_EMAILS=you@example.com
```

Every other variable is in [Configuration](/self-host/configuration).

## 3. Add the domains

In the **Domains** tab, add three domains, all with HTTPS and Let's Encrypt:

| Host | Service | Port |
| --- | --- | --- |
| `lumvika.example.com` | `app` | 3000 |
| `engine.example.com` | `engine` | 3000 |
| `files.example.com` | `storage` | 9000 |

The engine and the file store need their own domains: a browser connects to the engine directly to show a coworker's screen, and loads images straight from the file store.

## 4. Deploy

Click **Deploy**. When it finishes, check both domains:

```bash
curl -s https://lumvika.example.com/api/version
curl -s https://engine.example.com/health
```

Then [sign in](/self-host/install#2-sign-in).

## 5. Close the published ports

`docker-compose.yml` also publishes the app on port 3000, the engine on port 3001 and the file store on port 3002. Docker opens these ports past `ufw`, so close them in your provider's firewall, and keep only 22, 80 and 443 open.

## Updating

Click **Deploy** again: it pulls the images of the new version. The engine keeps its data in the `engine-data` volume, the database in `postgres-data` and the files in `storage-data`. The `migrate` step applies the database migrations a release adds before the app starts.
